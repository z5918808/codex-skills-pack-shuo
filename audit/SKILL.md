# Audit

Use `impeccable` for project design context. Audit observable implementation quality; do not turn taste into a fake technical failure.

## Scope

Check only relevant dimensions: accessibility, responsive behavior, runtime performance, states, theming/tokens, browser errors, and visible design drift.

- Use tools, screenshots, tests, and file coordinates; source inspection alone cannot prove runtime behavior.
- Separate verified defect, likely risk, and subjective preference.
- Assign severity from user impact and release risk, not issue count.
- Do not award numeric scores unless fixtures and scoring criteria make them comparable.
- Report systemic causes once, then list representative evidence.
- Include positive patterns worth preserving.

Output findings first: severity, location, evidence, impact, and smallest useful fix. Do not implement changes unless the user asks.
