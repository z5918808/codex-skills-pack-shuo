# Conditional Trio

Use for explicit Trio execution. Editing or discussing skills starts no tasks. Trio is a conditional workflow, not a required three-task roster. Apply [conditional routing](../../harness_docs/17_conditional_collaboration.md) as the single model-selection owner.

## Mandatory invocation gate

At every activation/resume, Main checks the existing TASK_GOAL.md for accumulated historical or duplicate content and proactively prunes it under [Repo Task Goal](C:/Users/user/.agents/skills/project-state-steward/references/task-goal.md) before new dispatch. The invocation includes this routine upkeep; do not wait for a separate cleanup request. Preserve active pins until their safe boundary.

Before implementation or dispatch, run [required decision gate process](../../harness_docs/18_conditional_gate_process.md): assess current facts, produce a hash-bound routing receipt, and check each selected action. Missing/stale routing evidence blocks the dependent action. Read-only fact collection needed for classification may proceed. Reassess changed scope, risk, failed approaches or owner; do not run a routing ceremony per mechanical item. Skill maintenance is exempt.

The routes are Luna-only for strictly eligible low-risk work, Luna then Sol for sustained implementation/digestion, Sol-only for small judgment-heavy work, and bounded Astra advice for the policy's explicit predicates. Luna/max is the long-running workhorse and owns huge data digestion. Sol Main/medium or a separate Sol/medium task resolves judgment and bounded repair, then hands remaining sustained work back to Luna. Astra is neither created nor messaged merely because the user said Trio.

## Roles and identity

- Main retains the user's actual selected model and user-facing task. Default Sol Main to GPT-6 Sol/medium for coordination, review and bounded interventions; an explicitly selected Astra Main defaults to high; a separate Sol reviewer defaults to medium. Never silently switch or create another Main. Titles identify roles, not runtime models. Record selected model and its source; unavailable runtime evidence stays unavailable.
- Worker is an on-demand persistent Luna/max task for the coherent execution/digestion segment. Give it requirements, allowed paths/actions, decision rules, decisive checks and a direct return address. It may implement and correct within assigned code scope; unrelated shared policy/infrastructure repair and consequential decisions return to Sol.
- Thinker is zero or one persistent Astra/high advisor, created/reused only after the routing gate identifies a concrete frontier decision or an explicit user override. It returns bounded analysis and uncertainty. Main resolves the decision and owns acceptance; advice is not clearance or authority.
- Reuse each needed role after its prior assignment is terminal, delivered, ingested and effects reconciled. No idle-role initialization, setup-only task, clone due to a new generation, or task-list omission treated as absence.

An explicit Trio execution invocation authorizes the conditional prescribed roles/models and scoped follow-ups, subject to existing task-bound model gates. Maintenance authorizes no dispatch. Keep the actual invocation text/date in the existing receipt. Native children never replace persistent roles; only a verified Luna/max root Worker may use its bounded depth-1 envelope after the existing parent/config gates. Sol/Astra never spawn. Extra persistent workers remain the explicitly authorized multi-workers route, never layered with native children.

## Ownership and acceptance

Main owns direction, authority/state, applicable readiness and acceptance. Luna owns its assigned sustained execution. Sol may take a bounded implementation/repair slice after safe-stop/terminal proof, effect and delivery reconciliation, and a fresh pinned executor/scope; use the shared routing transfer rules. A takeover does not authorize simultaneous writers, repeating completed operations, changing permissions or retaining the rest of a long run on Sol.

Luna-only needs the policy's low-risk eligibility and actual Luna ownership; do not call Sol-orchestrated work Luna-only. Sol reviews every delegated behavior-change result. Sol-authored work needs discriminating behavioral evidence, and any real independent-review requirement remains. Astra is used only for a current decision trigger, not routine opening/closing approval. Worker confidence, a second model's confidence, a local final or a delivery receipt is never acceptance.

Main starts review from requirements, diff, tests and Worker report. Expand to changed owners, callers, schemas or authoritative sources only for a concrete verification gap. Huge-data reports include source identities, coverage, counts, exceptions and traceable originals. Compression must preserve contradictions and missing coverage. Reuse unaffected verified work after corrections.

## Long-running contract and lifecycle

Sustained repo work uses one TASK_GOAL.md as Main's current goal prompt under [Repo Task Goal](C:/Users/user/.agents/skills/project-state-steward/references/task-goal.md). Main rewrites and prunes it at safe updates; keep current outcome, boundaries, completion criteria and required identity/reference fields, with history and receipts outside. Small/direct work creates no forced long-run scaffold. No native Goal mode, create_goal or substitute scheduler. Follow [local hook integration](../../hooks/JEV_MAIN.md) only for the existing eligible Main contract; it grants no dispatch or wake-up guarantee.

Do not overwrite an active pinned contract. Adopt these rules only after prior consumers are reconciled at a safe boundary. A skill edit does not migrate active projects. User stop revokes the current generation; resume requires fresh user authority. Never layer a new goal over unresolved effects or an unfinished assignment. Existing live/data, rollback and separation-of-duty gates remain binding.

## Required return and continuation

Each assigned Worker/Thinker directly sends its result/blocker to the pinned Main with an actual tool receipt before local final. Main consumes it, verifies the evidence and performs the next authorized action, dispatch, exact blocker report or completion. A failed return preserves the result and uses bounded reporting recovery; do not repeat completed execution or analysis to resend it.

After dispatch, Main may prepare one useful independent successor draft, then yields; after advisor dispatch, yield without duplicating its analysis. No wait_threads, sleep/read loops, polling, monitors, heartbeat or filler coordination. Direct delivery is required but does not guarantee runtime wake-up. One immediate snapshot is allowed only for dispatch identity/start reconciliation, delivered-event handling, or an explicit user status request, under the existing reference limits.

## Done

For delegated work Main issues ship/fix-first/rethink from current criteria and actual proof, with matching artifact/version/authority and all required returns consumed. For solo work verify the same requested outcome proportionally without inventing cross-task receipts. Reconcile owned processes/children and side effects; retire only roles actually used, after their lifecycle permits it. Report outcome, verification and material gaps, without invented progress percentages or quota savings.

Second failure changes strategy; third occurrence stops that strategy. Sol handles ordinary diagnosis; an unresolved consequential cause after two Sol approaches invokes the policy's Astra gate. Neither escalation nor task replacement resets failure history.
