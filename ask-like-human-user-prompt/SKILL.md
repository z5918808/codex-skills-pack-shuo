# Ask Like Human User Prompt

把使用者想追問另一位 agent 的檢查點，改寫成「像真人使用者在問」的 prompt。

目標不是寫技術審查表，而是讓接手 agent 被迫回頭檢查自己到底有沒有做完。問題要簡單、白話、直接，但要涵蓋功能、資料、流程、邊界、驗證、殘留風險。

## 何時使用

- 使用者要你「出 prompt 給另一個 agent 問它有沒有做好」。
- 使用者要 nontechy / 人話 / desperate user 版本。
- 使用者要確認某個 agent 剛剛是否真的執行到，不是只回報漂亮摘要。
- 使用者要多維度、全方位、on-point 的反問 prompt。

不要用在一般 code review、一般交接、一般 `/goal`、或需要你直接驗證本機 repo 的任務。

## 輸出原則

1. 只輸出可直接貼給另一位 agent 的 prompt。
2. 問法像使用者本人：白話、急切、不要專業術語堆疊。
3. 每題短，但要問到會暴露問題的地方。
4. 問「你有沒有真的做 / 有沒有親眼確認 / 有沒有跑過檢查」，不要只問「是不是可以」。
5. 聚焦使用者剛剛在乎的功能，不要發散成全專案稽核。
6. 問題要覆蓋多個角度：功能效果、資料來源、流程一致性、環境邊界、舊東西干擾、驗證證據、沒做的事。
7. 明確要求對方承認沒做、沒跑、只是推測。
8. 加一行安全邊界：不要 commit、push、清資料、關 browser、重跑高風險流程，除非使用者要求。

## 產出形狀

```text
你剛剛說有做好，但我想確認你是不是真的有把我剛剛在乎的功能做進去，不是只把表面整理好。

請你回頭檢查自己剛剛做的事，用白話回答：

1. 你有沒有真的 [核心功能 A]？
2. 你有沒有打開/跑過/親眼確認 [核心證據 A]？
3. 如果 [常見失敗情境]，現在會怎麼處理？
4. 你有沒有確認 [資料來源/狀態來源] 沒有看錯地方？
5. 你有沒有確認 [流程 A] 和 [流程 B] 用的是同一套東西，不會互相打架？
6. 你有沒有確認舊版/舊捷徑/舊資料不會干擾新版？
7. 你有沒有跑過對應檢查？沒跑就直接說沒跑。
8. 你剛剛有沒有任何一步其實只是推測？請直接列出來。

不要 [安全邊界]。
我不是要你重新做一次，我是要你檢查自己剛剛是否真的執行到。
```

## 寫法

- 開頭一句先定位使用者焦慮：「我不懂技術，我只想確認...」或「你剛剛說有做，但我想確認...」。
- 題數通常 6-10 題。
- 每題只問一件事，但要能逼出證據。
- 用「有沒有真的」「有沒有親眼確認」「沒跑就說沒跑」這類句型。
- 不要要求對方貼大量 log；可要求 PASS/FAIL 或一句證據。
- 若使用者指定某個 bug 或功能，前三題必須直打那個點。
- 若有環境或版本風險，問「會不會其實開到舊版」。
- 若有登入、cookie、profile、token、cache、port、資料庫、瀏覽器、部署環境，必問邊界是否混線。

## 最後一行

固定用這種收束，不要客套：

```text
我不是要你重新做一次，我是要你檢查自己剛剛是否真的執行到。
```
