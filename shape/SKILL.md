# Shape

This skill produces a compact design brief, not code. Use `impeccable` for established project design context.

## Discovery

Read existing product, content, components, constraints, and user evidence first. Ask only questions whose answers materially change the brief, one at a time when dialogue is needed.

Resolve:

- user, job, frequency, and mental state;
- primary action or decision;
- realistic content ranges and key states;
- brand and interaction character;
- technical, responsive, accessibility, and policy constraints;
- anti-goals and largest failure risk.

## Brief

Return: feature summary, user/job, success evidence, primary action, content and states, information hierarchy, interaction model, responsive strategy, visual thesis, constraints, anti-goals, open decisions, and implementation proof.

State assumptions separately from confirmed facts. Get user confirmation when the brief contains subjective product or brand choices that cannot be derived safely.

Stop after the brief; implementation belongs to the appropriate build skill.
