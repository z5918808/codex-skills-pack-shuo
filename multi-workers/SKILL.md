# Multi Workers

Use `/multi-workers`, `$multi-workers`, or “multi workers if needed” to accelerate an existing duo-run or astra-luna-duo. Keep its Main, goal and role ownership. Before expansion run the shared decision gate process（依主機正式的模型、路由及授權契約執行；本包不提供作者私有 gate） under multi-workers; volume/digestion stays Terra-owned, and extra workers still need this skill's explicit expansion approval. Skill editing starts no run; without an existing DUO, ask which DUO to extend rather than creating a new controller.

Main owns demanding planning, architecture, diagnosis, tradeoffs and acceptance; Terra owns execution. Task size does not transfer execution to Main. If splitting adds little value, keep the existing Worker and continue the DUO. This skill changes neither model effort nor the base workflow's explicitly permitted bounded repair exceptions.

When at least two meaningful execution branches can progress independently and the expected gain exceeds briefing, reporting and integration cost, suggest the split and ask once. Until approved, continue authorized work through the existing DUO. Reuse approval for the same goal; “if needed” alone is not approval. Do not invent roles or fill slots merely to increase Worker count.

After approval, follow the existing [DAG and reporting contract](../duo-run/references/dag-workers.md), reading and pinning applicable dispatch/lifecycle references before action. Use independent sidebar tasks, never subagents: at most five Terra medium Workers including pending creations, with A aggregating original evidence from B–E for Main. Reconcile A's current execution before assigning it the relay role. Release ready work without whole-batch waiting and keep conflicting writes serialized.

The shared contract governs transport, source preservation, stop and acceptance. Its small/direct allocation option does not apply to this DUO extension: no useful split means the existing Worker continues. Preserve current authority, model gates and worktree/external-action permissions; this skill grants no broader scope and starts no scheduler.

Maintenance only: check [scenarios](references/scenarios.md). Cost reduction remains unverified until observed in comparable work.

## Installation

Install the complete `duo-run` directory and `project-state-steward` with this skill; `astra-luna-duo` is optional when that compatibility entry owns the existing run. The host must provide persistent task identity, model selection, messaging and its applicable routing/authorization gates. An explicit expansion approval remains necessary; installation grants none.
