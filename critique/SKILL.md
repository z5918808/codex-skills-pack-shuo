# Critique

Use `impeccable` for product and brand context. Critique is qualitative design judgment; use `audit` for technical checks.

## Evidence

Inspect the real interface at representative desktop and mobile sizes when possible. Read relevant source only to explain visible behavior or constraints. If only screenshots or source are available, state what cannot be verified.

Independent reviewers or detectors are optional evidence, not mandatory ceremony. Use them only when they add a distinct signal and the active collaboration policy permits it.

## Review Lens

Judge the interface against its actual user and job:

- first-glance purpose and primary action;
- information hierarchy, grouping, and cognitive load;
- brand character and emotional fit;
- typography, color, composition, imagery, and rhythm;
- interaction discoverability, feedback, states, and recovery;
- responsive continuity and accessibility where visible;
- generic AI defaults or decoration without product meaning.

Do not apply a fixed aesthetic. Minimal, dense, playful, conservative, or maximal work can all be right for different contexts.

## Output

Lead with:

1. overall impression in two or three sentences;
2. two things worth preserving;
3. three to five priority issues, each with evidence, user impact, and a concrete direction;
4. one provocative question that could unlock a better concept;
5. the smallest relevant follow-up skill: `adapt` for context changes, `polish` for final cleanup, or `impeccable` for broader redesign.

Use severity only when it helps triage. Do not invent numeric scores for subjective critique.

Do not fix the interface unless the user asks. Do not force follow-up questions when findings already imply a clear next action.
