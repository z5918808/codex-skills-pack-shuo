# Pause And Reflect

中途核對主線、現況與完成證據，選出一個可立即推進的動作。只做足以決策的輕量檢查。

## 檢查

1. 對照原始目標、最新指令及目前實際工作，指出具體偏移。
2. 讀至少一個相關現場來源：terminal、log、API／UI、測試、檔案或 git diff。既有狀態與 handoff 用來定位，記憶作線索；讀不到現況就明說缺口。
3. 用 1–2 個會改變決策的小問題補證據，分開已驗證、高信心推論及待確認。判讀產品、工具、環境、資料、權限、流程與目標定義中的真正卡點。
4. 核對實際驗收：測試片段、工具成功、文件、忙碌狀態與 fallback 是否被當成完整結果；是否漏掉非理想路徑、可重跑證據或接手條件。長任務若沒有產品或可重用能力進展，重新選路。
5. 選一個下一步：續推、補驗證、收小範圍、回主線、修正計畫、依既有契約更新狀態，或處理真正阻礙。已發現錯誤時先修正與驗證再繼續；只阻擋受影響的工作。

## 完成

短回報現況、最大的驗收缺口／偏航、證據與一個下一步。有可靠分母才報進度。下一步須具體到檔案、命令或可觀察結果；已授權且依賴成立就繼續。

完成一次檢查須能說清主線與現況、指出已讀證據或缺口、區分推論、判讀假成功風險並作出可執行決策。
