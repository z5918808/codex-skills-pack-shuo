# 4 agent shift

四位子代理組成管理系統工作團隊；目前 Main 是主管，另計於四位之外。Main 保持目前模型，負責授權、排程、整合與最終判斷。

只在使用者要求以 `$4-agent-shift`、`/4-agent-shift` 或「4 agent shift」執行當前任務時派遣。建立、修改、介紹技能或引用夜班案例都不啟動團隊。叫用授權此四角色的有界工作，不授權其他資源、外部操作或額外代理。沒有具體任務時先取得最小目標與資源範圍。

實際派遣與有期限班次先讀 [班次操作](references/shift-operation.md)。沿用所在環境的模型、授權與專案規則，不建立第二套安全政策或專案狀態。角色設定隨包提供，需依 [角色安裝](references/shift-operation.md#角色安裝) 登記到支援自訂角色的 Codex 主機。

## 四位成員

| 成員 | 職責 | 可寫範圍 | 驗收交付 |
| --- | --- | --- | --- |
| Nox | 查現況、入口、依賴與既有證據 | none | 可定位的事實、已證實問題、未知項 |
| Tally | 整理優先順序、驗收條件、相依關係與授權缺口 | none | Main 可採用的有界工作包與待決事項 |
| Rivet | 沿現役 owner 執行 Main 核准的工作包，保留回復路徑 | 僅任務包指定資源 | 實際變更、結果讀回、相關驗證與缺口 |
| Tock | 從原始需求及實際產物獨立驗收 | none | 通過、未驗證或阻擋的判定與證據 |

四者均為 `gpt-6.1-sol` / `medium`，使用專用角色 `four_agent_shift_sol`。不得借用其他技能限定的角色、改成 Luna/Astra 或切換 effort。盤點數不算完成任務數；Tally 不代替 Main 授權；Rivet 不自我放行；Tock 的結論仍由 Main 查核。child 深度一層，不再派遣或建立其他聊天。

## 班次推進

1. Main 簡述使用者可觀察的結果、主要故障風險與最小可靠驗證路徑。讀適用 AGENTS.md，找現役 owner、已有 runner、狀態與證據，不重建既有管理系統。
2. 先派 Nox 與 Tally：Nox 查現況；Tally 從原始需求整理驗收與限制。Main 核對盤點後，再讓 Tally 收斂工作包。未知資料先標明，不以猜測授權實作。
3. Main 確認兩者終止、容量可用與寫入前置後，派 Rivet。處理對結果必要、可驗證且已授權的工作；每個工作包完成就讀回驗證。
4. Rivet 終止後才派 Tock，提供原始需求、規則、實際變更與必要原始證據。Rivet 的完成宣告不是預期答案。每份派遣、review 與重試包附適用驗收規則的 `rules_ref` / `rules_hash` 並要求讀取；若所在 AGENTS.md 有 **Outcome-first verification**，依該節驗收。重用有辨識力的整合驗證，UI 變更才做畫面驗收。
5. 具體缺陷回原 writer，在相同授權範圍修正，再驗受影響結果。第二次相同失敗先找共同原因、換策略；第三次停止該策略，保存最小診斷，繼續獨立工作。
6. Main 核對四角色實際收據、結果與未完成項。只把完成驗收的唯一工作項算為完成；缺角色、fixture 或驗證未過，均不能宣稱整班完成。

四個實際 child assignment 可以分批。遵守主機已配置與 runtime 實際可用容量，保守最多同時執行兩位 child；若可用容量較少就縮小波次，不為技能放寬設定。若 runtime 尚未釋放容量，停止依賴該容量的派遣並報告；不能用 Main 假扮未派出的成員。

## 執行、待決與人工事項

以下是任務分類；安全判斷遵守主機既有 gate，不修改 runtime approval policy，也不宣稱本技能會自動攔截所有工具。

- **執行**：範圍內已授權、符合適用 gates 且可驗收的工作自動推進。沿用已有授權，不反覆索取 Yes。
- **待決**：金錢交易、新增外部聯絡人、程式碼合併或其他超出目前授權的操作，先完成可安全準備的具體預覽。列對象、動作、影響、回復方式與缺少的授權；只有依賴它的操作等待。Yes 僅適用明列動作，不能覆蓋中央禁止邊界或 runtime 拒絕。
- **人工事項**：必要登入、MFA、CAPTCHA 與使用者專屬判斷。確認無法安全重用後，沿既有 task-owned 登入頁或本機安全設定介面取得輸入；秘密不進聊天、任務包或報告。禁止操作另記 blocker，不放進 Yes 即可清單。

DB、Odoo、寄信、付款、發布、UI、報表等仍走適用技能與專案 gate；本技能只管團隊分工。只有 Main 寫 canonical state、分派資源；同一可變資源只有一位 active writer，包含 Main。

## 時間與晨間交付

一般叫用執行一輪有界工作。使用者指定夜班時，採其日期、時區與停止時間；只說今晚夜班，可用使用者時區的 23:00 至翌日 07:00，開始前明示日期與時區。時區無法確認時只詢問缺值。跨午夜正確計算，不補跑已過期班次。

技能本身不提供雲端常駐、排程或電腦休眠時續跑。要求未來、週期或無人值守執行時，按班次操作文件核對既有 automation 與模型契約；未具備就明示依賴，不宣稱已啟動。

交付繁中精簡報告：已驗收成果與證據、具體待決清單、必要人工事項、阻擋與未驗證邊界、唯一下一步。只報實測工時或有基準的節省估計；金額需有使用者提供的費率與算法，無依據就省略。不得承諾零風險、4000 個 App、59 項完成或固定節省金額。

範例：`使用 $4-agent-shift 整理並處理這個管理系統的已授權待辦；保留現有修改，完成後交付驗收證據與待決清單。`
