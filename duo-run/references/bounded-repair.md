# Bounded repair and safe execution transfer

Read on a delivered defect/handoff. The shared conditional routing（主機 `17_conditional_collaboration.md`，本包未附） and gate process（主機 `18_conditional_gate_process.md`，本包未附） own model choice and transfer conditions; this reference owns repair evidence.

Sol Main/medium or a separate Sol 6.1/medium task diagnoses ordinary failures from delivered artifacts and current authoritative state. Start with requirements, diff, tests and report; expand to affected owners/callers only for a concrete gap. A local known implementation error may be corrected by Terra within its assigned scope. A repeated/shared cause, missing contract or unassigned infrastructure change returns to Sol. Do not send a vague retry or repeat the entire investigation.

Keep one writer. Before a bounded Sol takeover, reconcile the previous executor's terminal/safe-stop state, pending effects/processes and direct return. Pin the new executor, limited scope and current version/hash, then run the route/action check. Do not run an already completed command or grant yourself live authority through a repair label. A new route cannot clear a user stop or project separation-of-duty rule.

Use the smallest authorized correction and a discriminating behavioral regression at the real integration seam. Existing sufficient evidence may be reused; mirrored tests or a build alone do not prove restored behavior. Inspect actual command targets and effects: preview/test labels do not prove no-write. Use an isolated fixture when side effects are uncertain. Live/data gates, previews, rollback and fresh readback remain applicable to the named executor.

After two failed approaches reassess the shared cause and change strategy. Escalate to Astra only under the named shared predicate, such as unresolved consequential judgment after two Sol approaches; a decisively diagnosed fix needs no advisor ceremony. A third occurrence stops the failed strategy, and escalation does not reset history.

After the bounded repair, verify affected readiness and acceptance, reconcile ownership and dispatch remaining sustained implementation/digestion back to Terra using [lifecycle](lifecycle.md) and [dispatch](dispatch.md). Preserve valid completed work. A patch-local pass does not prove the caller works. Main performs acceptance from actual evidence under [acceptance](acceptance.md); high-risk or self-authored work retains required corroboration. Do not use Astra opinion as behavioral proof.

Direct dispatch/return yields under the existing reporting protocol. No cross-task polling, waits or approval-only pings. Unknown/failed returns preserve evidence for bounded recovery, never a duplicate production run.
