# Conditional Duo

Use for explicit Duo execution. Maintenance/discussion starts no tasks. Apply conditional routing（主機 `17_conditional_collaboration.md`，本包未附） and run required decision gate process（主機 `18_conditional_gate_process.md`，本包未附） before implementation or dispatch on every invocation. Missing/stale routing evidence stops the dependent action. Read-only classification can proceed; reassess material scope/risk/owner changes rather than every item.

## Allocation

At every activation/resume, Main checks the existing TASK_GOAL.md for accumulated historical or duplicate content and proactively prunes it under [Repo Task Goal](../project-state-steward/references/task-goal.md) before new dispatch. The invocation includes this routine upkeep; do not wait for a separate cleanup request. Preserve active pins until their safe boundary.

Recommend GPT-6.1 Sol/medium Main (including its own reviews and bounded interventions; a separate Sol reviewer defaults to medium) and Terra/medium Worker when sustained execution or huge data digestion justifies delegation. A triggered Astra advisor or explicitly selected Astra Main defaults to high under the shared route; preserve an actual selected effort. Strictly low-risk deterministic work can stay with a Terra activation task; a short judgment-heavy task stays with Sol. Sol does not replace Terra as the long-run workhorse: a bounded Sol diagnosis/repair ends with a safe handback of remaining execution. Work size alone never triggers Astra.

Keep the actual activation model, selected effort and user-facing task; do not silently switch or create another Main. If it is Astra, its work still consumes Astra usage. An explicit model pairing overrides recommendations for its scope; a legacy skill name alone does not force it. Use listed Terra and GPT-6.1 Sol at actual dispatch and existing task-bound authorization gates.

Main owns direction, acceptance, authoritative state and consequential diagnosis. Worker owns one coherent authorized implementation/digestion segment and its verification. Allow ordinary implementation choices and local corrections within assigned scope; shared authority/infrastructure changes, unresolved contract decisions and repeated failures return to Sol. No vague continue briefs or per-item handoff ceremony.

The normal delegated Duo has one Main and one Terra Worker. Add a bounded Astra decision assignment only when the shared gate names its trigger. It is conditional advice, not a second Reviewer or permanent third participant. Reuse a prior suitable advisor only after its assignment, delivery and effects are reconciled. Main consumes advice and retains acceptance; no routine Astra opening/closing call.

## Ownership and safe takeover

Before Sol directly takes a bounded Worker slice, reconcile its terminal/safe-stop state, pending effects, owned processes and returns; pin executor/scope/version at a safe boundary. Do not overlap writers or inherit live permission. Give remaining sustained work back to Terra. Project-specific separation of duties and data/live gates still bind.

Terra-only must satisfy all shared low-risk conditions. Delegated behavior changes receive Sol review. Sol-authored work needs decisive tests/readbacks and any applicable independent corroboration. A model's assurance cannot replace missing proof. High-risk Astra decisions must be resolved before dependent work, without bypassing authority or safety gates.

## Delegation and delivery

Persistent user-visible tasks are the cross-task route. Default Workers use Terra/medium and do not spawn native children. Sol 6.1/medium owns review. Explicit multi-workers（選用相依項目，須另行安裝） retains its separate approval and [A-E relay](references/dag-workers.md); it never follows merely from data volume. Existing pinned legacy helper assignments reconcile under their original rules before adoption.

Reuse healthy role tasks after terminal delivery/ingestion and effect reconciliation. Every assigned terminal result/blocker requires direct-message delivery and an actual receipt before local final. Main consumes the result into an authorized successor, exact blocker or completion. Failed delivery preserves the packet for bounded recovery, not repeated work.

Senders yield after substantive dispatch/return. No wait_threads, polling, sleep/read loops, heartbeat or monitoring. Delivery does not guarantee runtime wake-up. One immediate supported snapshot is permitted for dispatch/start identity, delivered-event reconciliation, or explicit user status, never a read loop. User stop revokes the assignment/generation; reconcile effects and require explicit resume authority.

## Done

Main accepts delegated results using current criteria, artifact identity, actual tests, authority and consumed returns. Solo work verifies the requested outcome without fabricated cross-task receipts. Reconcile all owned processes/children/effects; no duplicate execution, unresolved writer or missing required proof. Report the delivered result and gaps briefly. Preserve evidence and accepted outputs; claim no measured savings or reliability improvement from static routing tests.
