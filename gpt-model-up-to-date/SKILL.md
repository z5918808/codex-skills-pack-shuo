# GPT 模型更新

明確要求升版時，把授權範圍內應跟隨新版的設定改到實際可用的模型，核對相容性、每件合格交付成本與載入結果。全域範圍涵蓋本機已登錄的專案、使用者指定的工作根及它們的實際啟動依賴。僅叫用本技能時直接處理。與 [`$loop`](../loop/SKILL.md) 一起叫用時，由 Loop 在同一任務管理目標與接續，本技能提供完成條件。

## 查發布與生效設定

1. 從 OpenAI 官方公告、模型及定價文件確認發行版本。核對每個目標平台或 provider 在當期帳號可用的模型 ID、effort、必要工具和計價。Codex 沿主機現有的模型清單與 family 解析器確認實際 ID。API、CLI 及桌面會話各自核對可用性。
2. 從 Codex 專案清單、全域設定的專案登錄及適用的 `AGENTS.md` 確認範圍。查實際載入的全域 `config.toml`、agent profiles、技能及 harness，再追專案的 `.codex`、`.agents`、工作流、啟動器、容器設定和部署來源。搜尋舊模型 ID、family alias、`model_reasoning_effort`、角色和 `codex exec`。沿覆寫順序找出每個角色真正生效的模型與 effort，合併指到同一份設定的結果。生成設定沿原來源和重產入口更新。
3. 對 CLI 啟動器與 API 整合，從現役入口追到 route、adapter、CLI 參數或 API request，依專案契約確認啟用的 backend。CLI 路由核對實際帶入的 `--model`、effort、profile 與 `CODEX_HOME`。API 路由核對送出的模型和 effort。歷史 adapter、停用的 fallback、封存設定與在途任務的釘選紀錄保留供對帳，沿原生效入口更新。

## 更新與控制成本

- **同一模型系列。** 以原角色的 effort 更新現役舊版預設。例如舊版 Sol 改為當期最新且相容的 Sol。入口具備既有 alias 解析時可沿用 alias，派遣和驗收記具體 ID。固定版本的契約或評測基準依原 owner 處理。新版可用性或相容性缺口只影響相依入口。
- **全域同步。** 主機若已安裝模型同步工具，先用它的唯讀檢查模式確認同步範圍。確認命中的設定都是當次授權更新的預設後，沿同步工具更新。該工具涵蓋全域設定及指定角色／技能樣板。超出工具涵蓋的設定，沿各入口的來源檔更新。主機的自訂同步工具與派遣規則由使用者環境提供。共用設定混有固定版本時，只修改適用的欄位或呼叫端綁定。
- **跨系列或降低 effort。** 例行備料、欄位擷取和組包可比較 Terra／medium 與最新 Sol／low。用目前評測與定價作方向，重用仍適用的同類交付證據。缺對照時，用同一份代表輸入、工具及驗收條件小樣本驗證。依工作選掃描 PDF、尺寸圖等真正受影響的案例。符合品質且依既有預算合算時修改角色綁定。資料判讀見[成本比較實例](references/comparison-example.md)。
- **成本以合格件衡量。** 核對使用的訂閱／點數或 API 費率及模式。比較首審通過率、含重試與主責返工的耗時及用量，優先採用同等品質下成本較低的組合。每件更貴時，列出差額和實際節省的時間，依既有預算判斷。明列實測與估算，避免把 API 評測的單題成本折算成訂閱用量。

## 驗收與結束

沿各專案現有驗收規則、模型檢查與載入入口驗證。就改動的執行路徑確認生效檔、實際模型、effort 及代表性結果。可以重用同入口的有效證據，相關路徑有變才補最小隔離驗證。正式切換沿當次授權與既有部署 owner。設定已改、已實際載入和已通過工作驗收各自以證據確認。

所有可處理的生效入口更新並驗收後收尾。按專案或共用 owner 回報修改的位置、舊新模型／effort、可比成本及實際載入結果。入口已最新時記錄確認結果。相容性、模型尚未開放或其他阻礙須附具體證據，讓獨立項目繼續完成。
