# Handoff and lifecycle

## Start once and return directly

Resolve actual task/host IDs and a callable direct-message return tool before dispatch; missing persistent-task lifecycle or messaging blocks DUO, with no subagent fallback. Label existing Main `[Reviewer]` and Worker `[Worker]` without stacking prefixes or replacing the base title; if title controls are unavailable, identify roles in packets and disclose once.

Create one Worker with the complete initial goal, using existing model gates and authorized project/environment. Worktrees require approval. Record intended dispatch identity before creation. An ambiguous result permits one immediate inventory to reconcile identity, workspace, generation and prompt/hash; never blind duplicate creation. Preserve one proven OWNER, safely stop verified duplicates before authorized archival, and do not guess process ownership. One immediate read may verify a newly created/replacement Worker started; no repeated monitoring.

Worker sends results/errors to Astra once per complete segment or blocking exception, with compact coverage, artifacts/hashes, decisive evidence, unresolved gaps and owned-process/effect state. End in the same message with「依整體目標與目前進度，我下一步應完成哪個具體成果？」. It requests direction, not Worker planning authority.

Before sending, save a stable event_id, generation/assignment, destination, packet and pending delivery in the existing receipt. Call the actual tool, omit model/effort overrides (or preserve receiver settings if required), record success identity or locatable result, then end the turn. Local final text is not delivery; tool success is not consumption or guaranteed wake-up.

Definite correctable rejection permits one corrected retry. Ambiguous timeout remains unknown: no resend without supported idempotency or proof of non-delivery; event_id alone is insufficient. Failed recovery ends visibly with delivery_failed, redacted exact error, destination/event/assignment and missing action. Recover only unfinished sends on the next authorized entry.

## Reviewer continuation

Validate event identity, rules/goal hash, generation, evidence and stop state. Before effects, record consumed input and intended next action as pending; complete continuation only with actual dispatch receipt, verified local result, exact blocker or accepted completion. After interruption, reconcile actual effects and authority before finishing pending work; consumed input does not mean continuation completed, and duplicate input cannot repeat effects.

Astra handles the event in that turn: apply the main skill's review thinking, review/diagnose, then continue authorized work, dispatch a successor, identify an exact blocker or accept completion. No acknowledgement-only final, unsent plan treated as dispatch, or silent abandonment of an unfinished goal. Unknown/failed sends follow bounded recovery; stop/revocation overrides continuation.

After dispatch/return the sender yields. No wait_threads, cross-task polling, heartbeat, scheduler, watchers, artificial wake-ups or shadow execution. Explicit user status requests permit one immediate read snapshot and a status answer, never monitoring. One immediate event-handling snapshot may reconcile delivered evidence when needed. Normal work otherwise relies on direct messages. Account for any task-owned synchronous/background action after interruption; stop only verified stale owned processes.

## Goal reuse, stop and retirement

Never layer a goal over unfinished work. Before reusing the fixed goal path or changing pinned rules/ownership, prove prior generation terminal/stopped, no unresolved owned effects/successors and acceptance resolved or explicitly cancelled. Preserve outcomes, valid evidence and stop records in existing receipts, then issue a fresh generation under current authority. Old Workers cannot adopt a changed/missing file or recreate it. Do not require goal archives or create new controllers.

On user/Reviewer stop, latch generation revocation, send direct stop to Worker and halt successors. Worker checks stop/terminal state before other actions on every entry and safe boundary; start no new work, reconcile only an already-started action, deliver a missing stop receipt once and remain stopped. Idle UI or a receipt alone is not process termination proof. Resume requires fresh user authority and reconciled generation; automatic continuation, file deletion or prior permission does not revive stopped work.

This skill starts no native goals. Unexpected existing native goals require actual supported cancellation and readback; never invent a delete API, mark unfinished work complete or use archive as cancellation. If cancellation is unavailable, report the exact gap and keep execution revoked.

Reuse the healthy persistent Worker. Replacement requires explicit in-scope lifecycle authority plus terminal/stopped old work, reconciled effects, resolved review and proven unusable transport; never replace a merely slow task. No replacement after a user stop without fresh authority. After a permitted replacement, prove sole OWNER before authorized archival of the old task.

After ship, preserve deliverables/tests/referenced acceptance and rollback proof. Clean only verified task-owned disposable artifacts within authority; ambiguous/shared/user files remain. Goal overwrite/deletion requires the safe reuse checks above. Archive authorized Worker tasks only after terminal work, consumed returns and reconciled effects; retain Main as user entrypoint and record failed cleanup/archival as pending. No history purge or unknown-process termination. Optional cleanup does not revoke product acceptance.
