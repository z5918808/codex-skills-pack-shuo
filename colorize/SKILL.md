# Colorize

Use the project design context from `impeccable`; this skill adds a color system, not random saturation.

## Core Rule

Give each added color a semantic, hierarchical, or brand role.

1. Start from existing brand and state tokens.
2. Separate semantic status, interactive accent, data categories, and decorative color.
3. Use the fewest colors that preserve distinction.
4. Keep meaning consistent and provide non-color cues.
5. Test contrast in every state and theme; do not infer accessibility from hue names.
6. Use a perceptual color space when generating scales, but follow the project’s established system.

Do not hard-code green=success or red=error when domain or culture differs, enforce a 60/30/10 formula, ban pure neutrals universally, or use color where typography and spacing solve the hierarchy better.
