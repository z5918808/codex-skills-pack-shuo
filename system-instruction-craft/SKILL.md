# System Instruction Craft

判斷本次發現是否值得成為 agent 規則，放到負責該行為的既有位置。先確認原始證據、重用情況與實際缺口，再提出或套用最小修正。

## 放置判斷

| 去處 | 條件 |
| --- | --- |
| 全域 AGENTS.md | 多數任務都需要的判斷順序、驗收或溝通規則，值得持續載入，且已授權全域修改 |
| Repo AGENTS.md | 依賴專案結構、入口、產品或在其他 repo 會造成誤導 |
| Skill／條件參考 | 只在特定工作或分支需要的方法，能用明確觸發指標找到 |
| 原 topic／證據文件 | 暫時 workaround、單次事件或尚未驗證的發現 |
| 捨棄 | 已有 owner 的同義規則、無行為差異的口號，或缺少重用理由 |

只有使用者明確要求同步全域與 repo，且兩者都有必要時才改兩處。每個意思保留一個 owner，其餘位置以指標引用。

## 修訂

1. 從本輪檔案、命令、現況與使用者要求定位發現，壓成一句會改變行為的候選規則。
2. 讀目標文件，指出現有哪個段落不足、為何此處適合、需要哪些檔案及維護取捨。沿目前結構，避免套用舊章節名。
3. 核對既有授權。已要求修訂指定範圍就繼續；只有建議或需要修改範圍外的全域文件時，先提出可審閱文字與缺少的授權。
4. 在正確 owner 原位更新最小段落。保持無關發現、專案特定經驗及全域規則各自的範圍。
5. 讀回修正及受影響引用，確認可發現、沒有重複規則，並保留既有權限與驗收。需要包裝 skill 時載入 `skill-creator`。

完成回報實際變更、放置理由、驗證與尚未證實的效果。文件要求與工具執行攔截分開，只有規則文字時不聲稱已自動強制。
